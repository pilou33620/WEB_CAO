# WEB_CAO -- dependances Python
#
# Aucune. Volontairement.
#
#     pip install -r requirements.txt      # n'installe rien, et c'est le but
#
# Tout le code Python du depot n'utilise que la bibliotheque standard :
#
#   serveur.py                              http.server, socketserver, ssl,
#                                           webbrowser, argparse
#   passerelle_mcp.py                       urllib.request, json, threading
#   commun/outils/monofichier.py            assemblage du HTML autonome
#   editeur-pcb/outils/*.py
#   editeur-schematique/outils/*.py
#
# Verifie sur Python 3.10 et 3.12 (l'integration continue utilise 3.12).
#
# Ce fichier existe pour rendre la garantie explicite et verifiable : le jour
# ou une ligne de paquet y apparait, le depot perd ce qui fait son interet --
# un double-clic sur serveur.py fonctionne sur n'importe quelle machine ou
# Python est installe, sans reseau, sans environnement virtuel, sans droits
# d'administration, sans proxy d'entreprise a negocier.
#
# C'est pour cette raison que serveur-composants.py (FastAPI + uvicorn +
# pydantic, port 8420) a ete supprime : il exposait les deux memes routes
# /api/tools et /api/tool que serveur.py, alors que toute la logique de
# protocole MCP vit dans passerelle_mcp.py, en bibliotheque standard.
#
# Les bancs d'essai tournent sous Node, pas sous Python (voir README.md) ; le
# paquet npm facultatif « canvas » n'a rien a faire ici.
#
# -----------------------------------------------------------------------------
# UNE EXCEPTION, ET ELLE EST HORS DE CE FICHIER : le solveur electromagnetique
#
# python/ligne_mom.py -- methode des moments sur la section droite, qui donne
# l'impedance d'une piste -- a besoin de NUMPY, et de numpy seul. Ce paquet
# n'est PAS liste ici, et ce n'est pas un oubli : la garantie ci-dessus tient
# toujours, parce que rien de ce que le depot fait par ailleurs n'en depend.
#
# SCIPY N'EST PAS UNE DEPENDANCE DU SOLVEUR, contrairement a ce que trois
# messages de ce depot ont longtemps affirme. Seul le banc d'essai l'importe,
# pour les integrales elliptiques de son etalon de triplaque -- et un banc
# d'essai n'a pas a peser sur ce qu'il faut installer pour se servir de
# l'outil. (mom_solver/, le moteur 2,5D pleine onde livre a part, demande bien
# numpy, scipy et numba -- mais il n'est pas dans le chemin de calcul.)
#
#   · les deux editeurs s'ouvrent en double-clic, sans Python du tout ;
#   · serveur.py demarre, sert les pages, la recherche de composants, les
#     profils, les projets et la lecture IPC-2581 sans numpy ;
#   · seule la route /api/simulation manque a l'appel. Elle repond alors 503 en
#     nommant ce qui manque, le panneau « Simulation EM » l'affiche, et son
#     bouton « Exporter .json » continue de servir : le probleme s'enregistre et
#     se donne au solveur en ligne de commande sur une autre machine.
#
# Autrement dit : ce paquet achete une fonction de plus, il n'est le prix
# d'aucune de celles qui existaient. L'ecrire ici le rendrait
# obligatoire -- « pip install -r requirements.txt » echouerait derriere un
# proxy d'entreprise, et le depot perdrait exactement ce que ce fichier
# protege. Pour s'en servir :
#
#     pip install numpy
#
# Le banc d'essai du solveur se lance sans pytest. Lui seul demande scipy :
#
#     pip install scipy
#     python python/test/banc-ligne-mom.py
